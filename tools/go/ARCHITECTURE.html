The Go runner, at a glance

A single package main CLI: reviewed JSON tables supply patch facts, the registry supplies canonical English, and shared Go logic plans and validates changes. Scoped operations can be enhanced without reproducing every historical script.

Shared Go toolkit with explicit coverage limits. See the current family coverage and owner map for verified progress. The full probe pipeline remains Python-owned and is migrated last. Recipe counts and historical dispositions do not establish gameplay or full migration.

Registry document policy belongs to authorRegistry, separate from routing and image patchCopy. Reference discovery uses an advisory glyph projection: its high-half heuristic does not prove register liveness, reachability, or exhaustive references.

reference_cohort preserves declarative pointer occurrences and reports explicit nominal comparisons through the existing font and grammar owners. Its separate source-policy phase retains bounded raw observations and shared graph facts, with known hazards ahead of UNKNOWN. The contract and synthetic example do not establish an actual game census, safe landing, alias write or physical fit.

reference_observed reports each declared registry site and its observed words through references; it requires a pinned ELF and registry, without candidate search or a glyphmap. normalizeReference shares geometry across expected pointer planning, append and the strict report. referenceTarget shares observed opcode/register checks and target reconstruction across append and the report. Expected planning remains separate from observed reads. The existing inspect ELF mapper classifies complete four-byte site words and one-byte target points. Multiple targets stay visible; missing, malformed or unmapped sites never fall back to the registry ID. A decoded target can be BSS or unmapped, and a mapped point does not establish readable stream contents, liveness or patch authority. reference_candidates retains its separate advisory heuristic.

--stream-audit-profile selects the separate read-only auditStreams lifecycle and forbids other workflow inputs. The profile pins both source files and the glyphmap; readInput reads bounded JSON inputs, while binary sources use bounded ReaderAt windows and complete streaming hash/identity rechecks before stdout. The existing controls decoder preserves opaque payload boundaries. Explicit decoder style is required; no new decoder or handler per patch is added. Exact span equality, through-END equality and semantic comparisons remain distinct. Raw span facts remain known when decoding fails; semantic comparisons become unknown. Plain paired facts do not generate canonical wording, approve placement or prove gameplay.

Optional observed_family adds a fourth pinned source, registry, to the same lifecycle. auditStreams reuses references with reference_observed and the inspect ELF mapper; no new function, type or decoder is added. The selected family must exactly match the normalized audit IDs. Every declared site must be valid, with at least one site and one shared target per ID. The complete observed window, including bytes after END, must map as one file-backed span at that target and exactly match the explicit file range. Missing, divergent, BSS or unmapped bindings fail before JSON publication, without an ID fallback. Successful reports retain observed_references and full observed_mappings. The observed ELF and registry are bounded at 64 MiB each; the reference source can still stream larger files.

The reference-bound audit example uses five runtime files totaling 7,762 bytes. Plain three-input audits keep their existing byte-comparison behavior. The separate native source-only self-comparison covers three short labels (DF, MG and HP), eight sites and sixteen words; it proves no English wording, sentinel handling, liveness or fit. Stored registry references do not establish live runtime consumers.

An entry can add an explicit canonical no-wrap or character-budget policy to the same bound lifecycle. Pinned registry English and the original window feed existing controls readiness and encode; the resulting third stream shares the scanner and comparison loop. Generated spans are buffer offsets. Unsupported generation keeps independent observations and omits canonical comparison; the original status still describes reference versus observed. Strict declared sites, full-window mapping and input rechecks remain mandatory. The canonical audit example does not establish native fit, whole-ledger parity or gameplay.

Existing encode preserves a proven payload-free leading setup/non-scale pen prefix in source order. It reuses controls for the source prefix and strict generated body, keeping prefix words outside the character budget. Headerless setup is supported for expected-stream generation; colour, opaque payloads, native fit and complete append/write validation remain separate. This adds no function, type or mode flag.
